{% comment %} The attachments dialog: where attachments are both read and edited. One dialog serves the whole Completion block. An assignee's attachments for their part are one note and a list of links (up to ``attachment_limit``). Either may be empty. The dialog shows the note on top and the links under it as a table, in both of its modes: view Opened by View attachments in a Done cell (task_attachments_line.html) with a ``view-attachments`` window event whose detail fills it in: name whose part, for the title ("Bob", or "your part") attachments {links: [...], note: "..."} updated when it last changed, as display text, or "" own whether it is the viewer's own part canEdit whether the viewer may change it now (their own part, done, not yet reviewed or verified) When it last changed is shown under the title, in the header. The links come first, the note under them. Each row of the table numbers a link, shows it in full so the reader sees where it really goes, and has its own button opening it in a new tab, without the opener or the referrer: Open, or on a link to another host Open external with an external-link icon. External is judged as the site's "Leaving i-CONNECTS" dialog (base.html) judges it: a different host from this page is leaving, the same host is not. The buttons are plain links rather than ones marked data-external-link: Open external already says where it goes, so the site's leaving dialog is not put in front of it. With ``canEdit``, Add / Edit attachments switches it to edit mode; on the viewer's own part once reviewed or verified, it says instead that unticking Done is the way to change it. edit The same layout as a form: the note as a text box on top, the links as a table of link fields with Remove on each row, and Add another link under it (switched off at the limit). It starts from the viewer's saved attachments each time (``my_state.own_attachments``, kept from an earlier mark they may since have undone), with one empty link row when they have none, so Cancel discards any change: back to view mode when it came from there, closed when it did not. Opened straight in this mode by an ``open-attachments`` window event, from the viewer's own Done tick or the plain layout's Mark my part done button. Saving posts the note and one ``attachment_url`` per row, in order, with ``attachment_list`` marking the post as carrying attachments even with no rows (forms.AttachmentsForm). It replaces what was there; clearing the note and removing every link clears it. Blank rows are dropped. Which endpoint it posts to is decided when the block renders, since the block is swapped after every change: not done yet "Mark done": tasks:complete, marking the part done and saving the attachments together. done "Save attachments": tasks:attachments. A refusal (a link that is not http/https, too many links, a note too long, or attachments frozen by a review) comes back as a 400 whose text — naming the row, as "Link 2: …" — is shown above the buttons. The edit mode is only rendered for an assignee (``my_state``). Who sees the attachments is decided before this point: View attachments is only drawn for the assignee, the task's reviewers and its Leads.
