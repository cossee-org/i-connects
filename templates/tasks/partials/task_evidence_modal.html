{% comment %} The assignee's evidence dialog, in the app's standard modal (the same shape as task_member_type_modal.html). It opens on an ``open-evidence`` window event, from the viewer's own Done tick, the plain layout's Mark my part done button, or Add / Edit evidence in the evidence viewer (task_evidence_view_modal.html). The evidence is a list: each row is one item, a link and a note, either of which may be left empty (a row with neither is dropped). Add another link appends a row, up to ``my_state.evidence_limit``; Remove takes one out. Each opening starts again from the viewer's saved items — kept from an earlier mark they may since have undone — so cancelling discards any rows changed; with none saved it starts with one empty row. Saving sends the whole list, which replaces what was there; removing every row and saving clears it. The rows post as repeated ``evidence_url`` / ``evidence_note`` fields, in order, with ``evidence_list`` marking the post as carrying a list even when it has no rows (forms.EvidenceListForm). It does one of two things, decided when the block renders, since the block is swapped after every change: not done yet "Mark done": posts tasks:complete with the list, so the part is marked done and the evidence saved together. done "Save evidence": posts tasks:evidence. Only offered while the part is not yet reviewed or verified (``s.can_edit_evidence``). A refusal (a link that is not http/https, too many items, or evidence frozen by a review) comes back as a 400 whose text — naming the item, as "Item 2: …" — is shown above the buttons. Who sees the evidence is said in the dialog, because it is not everyone on the project: the task's reviewers and its Leads.
